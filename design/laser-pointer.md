# 激光笔：非致命激光枪的常亮变体

2026-09-24。Q1–Q12均选A后，用户明确“按此实现”，完整方案已确认。现已实现v1.13.0-laser-pointer并完成主要隔离验收，源码合入主目录；本轮未安装。已保留同期安装的v1.12非正面致盲功能，激光笔自身仍严格要求正面/斜前方。验收、产物与边界见[激光笔实验记录](../knowledge/experiments/laser-pointer-20260924.md)。

## 用户已明确的规则

- 新武器「激光笔」，为非致命激光枪的变体。
- 鼠标左键点击一次点亮，保持常亮；再次点击熄灭，不能变成长按才亮或长按反复切换。
- 常亮期间按一定速度消耗原版电池，无弹匣设置。
- 没有辅助瞄准；只要光束扫到敌人眼睛就立即使其失明一段时间，不预设停留蓄积门槛。

## 已确认整体方案

| 项目 | 完整行为 |
| --- | --- |
| 操作 | 一次左键点亮，再点熄灭；长按只触发一次。没有弹匣、装填、瞄准辅助或SATS排队。遵守原生攻击键绑定和界面/焦点限制。 |
| 耗电 | 随身原版batt，默认2份/秒；预付一份后按亮灯时间使用，剩余电量跨开关、切枪和存读档保存；耗尽自动熄灭，补电后须手动点亮。 |
| 命中 | 手动直线扫眼，正面/斜前方生效；立即致盲6秒，可持续刷新。墙体、身体与护盾按实际遮挡，首个碰撞即止；无跳弹、智能制导、额外命中抽签。 |
| 失明 | 沿用原枪零直接生命伤害、失去玩家实时感知与恐慌乱攻；有眼生物及机器/炮塔传感器，首领同样6秒。两武器取现有剩余与本次基础时长较大值，不累加。 |
| 时间 | 失明倒数随敌人行动时间；玩家在时停中可操作时，光束即时跟随并正常耗电，不录制/回放。普通暂停冻结光束状态、扣电和新命中。 |
| 中断 | 切枪、收枪、Pip、SATS后熄灭，返回须再点；死亡、换图、读档从关闭开始。普通关灯不取消已施加失明。 |
| 外观与获得 | 沿用原激光手枪手持外形，独立名称「激光笔」；清晰细光束、落点光点、失明状态/倒数，无辅助眼圈。每存档首次启用赠一支、不赠电池、不重复赠送。 |

### 随整体方案确认的补充边界

- 首版由玩家使用，只对存活敌对目标直接施加失明。恐慌攻击可误伤同伴、中立或玩家并间接致死，射手阵营不变；近战乱挥、移动敌人小范围乱走、固定炮塔原地乱转乱攻，不赋予原本没有的行动能力。恢复后保持警戒并正常重新发现玩家。
- 不额外增加头盔/装甲外观免疫；炮塔传感器需露出，不能唤醒原本停机或剧情禁用的单位。激光自身不扣血，不附加击退、着火或爆炸。
- 射线最长沿用2000场景像素；眼区基础半径默认6px，按体型缩放后限制在3–10px。独立默认值固定取上述初值，不随原枪之后的设置或非正面开关改变。
- Pip/MSW及F6增加「激光笔」设置页，不加热键：独立功能开关默认开、失明时长0.5–30秒/步长0.5/默认6、眼区半径3–10px/步长0.5/默认6、耗电0.1–10份每秒/步长0.1/默认2、命中调试标志默认关，保存和恢复默认只作用于此页。无弹匣/装填/辅助/SATS数值入口。
- 使用时显示亮灭、随身电池和已付电量余量，避免0/0弹匣显示；装备激光笔时显示受控敌人状态倒数。光束为持续更新的一个视觉对象，不反复播放单发射击的闪烁/声音。
- 保存的是未用完的电池比例，修改耗电速度只改变之后使用速度，不增加或抹去已付电量；仅扣随身库存，不能隔空调用仓库。亮灭状态和临时恐慌接管不作为永久状态保存。
- 失去玩家操控（如剧情接管、攻击回放）时熄灭并停止扣电，恢复操作后手动点亮；普通暂停仍按Q3冻结后恢复。设置中禁用某武器时清理它的效果贡献，不误清另一武器尚有效的失明。
- 快速扫过眼区需要补检两次更新间的路径，每次检查仍遵守首个障碍和朝向；不得用隐藏吸眼、大眼区或穿墙扇形代替。实际连续采样边界须通过运行验证，不宣称数学上绝不漏判。

### 实现与验收范围

- 独立武器身份、按键切换和库存计费；复用眼位/遮挡与恐慌能力，但分离配置和控制来源，保证两把武器交替命中、禁用、死亡及恢复时只推进一次敌人状态。
- 验证真实装备、切枪、保存、读档后的光束/眼部命中；静止、移动敌人、快速扫掠、背面、墙后、身体和护盾边界；普通生物、近战、移动机器、8类炮塔与首领覆盖。
- 验证长按仅切换一次、短点累计付费、30秒60电池、余量跨读档、耗尽关闭、补电不自启、无仓库扣费；暂停、SATS拒绝排队、真实Sandevistan即时扫盲/正常耗电且不重放。
- 验证清晰常亮束和落点、无辅助圈、设置独立、两武器计时取较长且不重复接管；回归原枪读档与现有智能/跳弹功能。最终以准确生产SWF验证，不用仅开发构建通过代替正式字节。
- 数值和显示易调整；新增武器和余量会写入存档，先在隔离存档验证一次赠送和真实读档。主要未验风险是快速扫掠漏眼区、时停重复/漏扣电，以及共享失明控制恢复异常。最坏情况下可能耗电却未致盲或敌人未正常恢复，因此这些必须作为验收项，不能以单发枪已有测试替代。
- 已实现独立常亮武器、帧间扫眼、库存余量和共享失明来源管理，准确生产候选已跑真实存读档、40类目标与真实时停。保留同期非正面功能；正式release仍为v1.12，未用候选覆盖。

## 设计阶段已读源码事实（历史核查）

- 原枪MSWLaser.fire在一次射击里作几何射线、施加失明并生成MSWLaserBeam；现有Beam为4次世界步消退，不能仅无限重播开枪动画充当常亮实现。
- 原枪耗弹由MSWDazzlerWeapon.shoot调用原生Weapon.shoot后固定扣弹，configure仍有holder/rashod/reload。变体的无弹匣连续库存消费需要独立处理。
- MSWBlindController已支持命中刷新，其计时在插入敌人前方的世界节点推进；单独把光束隐藏和解除已施加失明不应混成同一操作。变体刷新语义按Q1/Q12与上方整体稿落实。
- 当前控制器与MSWLaser.frame的清理受原枪laserEnabled绑定；两武器独立配置后需协调同一单位的失明接管，避免两个控制器重复推进AI，或关原枪时误清激光笔效果。这是实现责任，不另向用户询问代码结构。
- 初始核查时6-turret-sensors尚未提交；Q10时重查已由另一任务提交0f42e15并安装。正式文件哈希C233D67EA0C5FC74BD0499ADFB1AD1C45823CAEEDA7145806D84BE101ABF0827。本轮只读核对，不把其他任务的炮塔实测当成本变体已验证。
- 原生输入Ctr.onMouseDown1置keyAttack，松开清除；UnitPlayer每个玩家步重复attack()。不能将每次attack调用当作新点击。原生消费按键（attack返回false）或按下沿锁存可用，但须遵守菜单、焦点、改键等限制，并排除SATS/autoAttack/attackForever误触发。
- Weapon的holder=0同时跳过装填和原生耗弹；需专用库存扣费。原生reloadWeapon同时维护items[ammo].kol和mass[2]；Invent.minusItem在随身不足时还会扣vault，不能直接用它隔空取电。库存数量仍应为整数，按时间消费需保留电量余数。GUI.setHolder对普通无匣枪仍可显示0/0，须专门处理激光笔状态/剩余电池显示。
- castRay只检测当前射线，没有两次更新间的扫掠；快速扫过或敌人横穿可漏眼区。补中间样本时每条射线仍需遮挡校验，不能把大扇形当穿墙命中。用户“扫到立即”已明确，不再询问是否需要曝光蓄积。
- World在非暂停时推进Location，Location先玩家步后物体链；玩家武器步和敌人步在时停中并非同一时钟。ENTER_FRAME暂停时仍会运行，不能不加门控地扣电/刷新失明。枪口getBulXY依赖显示对象，冻结时只改逻辑坐标会留旧起点（公共weapon-vis-frozen-world.md）。单发枪的录制/回放实测不能证明常亮束兼容。
